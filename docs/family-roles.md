# 亲友团身份与权限（方案摘要）

目标：把链接发给不同人时，各自有身份；爸爸/妈妈是管理员，爷爷奶奶等亲友权限更窄。先规划，分几期落地；本版只写方案，不写完整权限代码。

## 与现有同步密钥的关系

- 现在全家共用一把**同步密钥**：能解密云端事项、生长记录、相册元数据；密钥即「全家数据门禁」。
- 权限系统应叠在密钥之上，而不是取代它：
  - **仍要密钥**：没有密钥解不开密文。
  - **再加角色**：有了密钥之后，再决定「能改什么、能传什么」。
- 短期可继续「一把密钥 + 本机角色标记」；中期再考虑「邀请令牌带角色」，避免把密钥随便发给只读亲友。

## 角色建议

| 角色 | 典型人 | 权限 |
|------|--------|------|
| 管理员 | 爸爸、妈妈 | 全部读写：事项/疫苗/生长/用药/相册上传下载、设置、邀请与踢人、改宝宝资料 |
| 亲友（可传图） | 爷爷奶奶、常来的亲戚 | 看事项与相册缩略图；可上传照片/视频与备注；不能改疫苗计划、删除他人事项、改同步/照片服务设置 |
| 只读亲友 | 远房亲戚、朋友 | 仅浏览日程摘要与相册（可选隐藏用药细节）；不能上传、不能改任何资料 |
| （可选）访客 | 临时 | 限时只读链接，过期失效 |

## 要不要账号登录

- **一期不必做完整账号体系**（省去注册/找回密码）。
- 推荐：**邀请链接 + 本机身份**。管理员生成链接（含空间 id、角色、短期签名）；对方打开后输入昵称，本机记下 `role`；同步仍用管理员下发的密钥片段或由管理员代开一次「加入」。
- **二期**若亲友变多、要撤销权限：再上轻量账号（手机号/微信），或「设备列表 + 吊销」。
- 完整账号（邮箱密码、OAuth）放到更后面；当前家庭规模用邀请链接足够。

## 邀请链接怎么带角色

示例语义（实现时再定编码）：

`https://…/baby-record/#/join?space=…&role=relative_upload&exp=…&sig=…`

- `role`：admin / relative_upload / relative_readonly
- `exp` + `sig`：防篡改、可过期
- 打开后：写入本机 `settings.memberRole`、`settings.memberName`；UI 按角色隐藏「删除 / 设置 / 疫苗计划」等入口
- 管理员可在设置里「亲友团」查看已加入昵称、改角色、作废链接（二期需服务端成员表）

## 分几期落地

1. **一期（本版前后可排）**  
   - 本机可选身份：爸爸 / 妈妈 / 爷爷 / 奶奶 / 其他（写入 profile 同步字段，仅展示用）。  
   - 相册时间轴「第 X 天」等展示优化（已做）。  
   - 权限仍是「有密钥＝全能」；先把亲友团 UI 骨架和文案做出来，不挡正式账号。

2. **二期**  
   - 邀请链接带角色；本机按角色隐藏危险操作。  
   - 云端可选：成员列表（昵称、角色、最后同步时间），管理员可作废。  
   - 相册上传对「可传图」开放；设置页仅管理员可见。

3. **三期**  
   - 真正吊销：换同步密钥或按成员封禁拉取；只读不再下发完整密钥。  
   - 按需加登录；照片服务鉴权与角色对齐（Tunnel HTTPS 之后）。

## 风险与原则

- 不要把同步密钥印在公开邀请页；只读亲友尽量用「受限令牌」而不是万能密钥。  
- 管理员操作（删事项、改生日、关同步）必须二次确认。  
- 本地数据在：即使云端权限做错，家里手机仍可导出备份后再迁。
