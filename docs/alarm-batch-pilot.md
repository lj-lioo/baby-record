# iPhone 批量更新闹钟真机联调

从改期后的闹钟面板点「定向替换这项闹钟」，也可以对多个已改期事项发起一组。App 显示涉及的事项编号和旧、新响铃时间。iPhone 的「宝宝闹钟批量更新」快捷指令负责实际操作提醒事项。首次配置先在专用测试列表验证。可在苹果快捷指令中分享已验证的指令。

## 独立快捷指令

在 iPhone 上新建「宝宝闹钟批量更新」。如果 App 修改了闹钟基础名称，名称使用该基础名称加「批量更新」。不要在已有「宝宝闹钟仅创建」中添加查找、修改或删除动作，也不要调用旧删除指令。

快捷指令从「快捷指令输入」获取 JSON 文本，并用「从输入中获取字典」解析。可先只做预览分支，得到真实提醒对象和字段后再接入写入动作。

- 验证 protocol 严格等于 babyrecord-alarm-batch-v1，list 等于 宝宝，groups 非空。新建测试版先固定选择一个专用测试列表，正式版在 iPhone 动作中固定选择真实的「宝宝」列表对象。列表选择使用系统对象，避免同名列表。
- 每组的 tag 要完整匹配 ^<宝宝#[0-9a-z]+>$，在整组中唯一。remove、keep 是旧时间的数组，create 包含 minute、title、notes。时间是本机 yyyy-MM-dd'T'HH:mm。验证时间能解析且按原格式往返相等；每组内同一时刻只出现一次。所有 create 的备注必须以本组 tag 原样结尾。
- 先对所有组做只读检查。在固定列表内只检查未完成提醒。用备注完整结尾与本组 tag 比较，再把系统提醒的响铃日期格式化到分钟并比较。查找条件均为「全部」。每个 remove 和 keep 冗余核对后都必须唯一匹配到一个提醒对象。查不到或找到两条就停止；不要退回按标题、按整个列表或按空匹配。
- 如果 create 的目标时间已存在本组提醒，只有当它唯一且完整标题、备注都与拟创建项相等时可复用。否则先停止核查，避免补建重复条目。对尚未建的 create 收集创建参数。任何一个旧提醒对象都不得加入移除列表两次，也不能同时出现在保留和移除列表里。
- 把本组旧 → 新时间、要保留的条目及真正要移除的对象一起预览，确认一次。用已有创建专用流程的「添加新提醒事项」动作，为缺少的新提醒设置正确时间和「紧急」。复查所有新提醒的时间和数量；创建失败或无法验证时立即停止，保留整组旧提醒并报告已成功新增的条数。
- 重新检查旧对象和刚确认的新对象；检查仍必须唯一。一次性将**之前明确收集并核对的待移除提醒对象**传入「移除提醒事项」。保留 iOS 删除确认，完成后重新查找，确认指定旧条目消失以及新提醒仍在。只有整个结果都成立才显示「全部成功」。如果中途失败，报告成功和未确认的数量，不自动用更宽的范围重试。
- 最后一轮核对通过后，用「文本」动作生成 `BABY_ALARM_REPLACED`，将这一段文本传给「停止并输出」。将这个动作放在唯一的成功分支。查不到、匹配重复、取消或部分失败时，输出错误提示并结束。App 收到这个固定回执后会复核所有事项的原、新时间，匹配时自动标为已设置。若 iPhone 打开了 Safari 回执页，看到「回执已送达」后切回主屏幕上的 App。

## 必须用真机验证的行为

1. 先新建专用列表「宝宝闹钟测试」，并在测试指令中固定选择这个列表。放入一条带编号的周二测试提醒和一条同名、同时间但编号不同的提醒。用周二改周四的测试载荷核对，确认前者替换成功，后者保留。再在测试列表中放入 7 条同一事项、不同时间的紧急提醒，并加入一条无编号的同名提醒，以及另一列表中的同编号提醒，验证同一批只替换这 7 条。
2. 故意去掉一条旧提醒或复制一条旧提醒。验证同一批里没有任何老提醒被删除。
3. 保留一个不变时刻，手动造一个冲突的新时刻，分别验证保留和停止。再验证取消、创建失败、锁屏响铃以及 iCloud 同步后数量。
4. 检查本机提醒日期字段的映射、格式化时区、紧急状态及对象选择在目标 iOS 版本里的行为。完成后在苹果快捷指令里导出或分享该指令。

网页回归测试运行 node --experimental-vm-modules test/alarm-tag-ui.mjs。它覆盖网页提供的范围、批量载荷和状态，不能替代上述真机联调。
